## 0. 영상 ⑫~⑱ 한 장 요약

| 챕터 | 한 줄 요약 |
|---|---|
| ⑫ 구분과 위치 | `스킬 = 방법 · 커넥터 = 연결 · 플러그인 = 꾸러미`. 찾는 곳: **+ 버튼**(바로 쓰기)과 **Customize**(한곳에서 관리) |
| ⑬ 슬래시 | `/`를 치면 스킬 목록. 직접 부르기(`/`) 또는 클로드가 필요할 때 알아서 |
| ⑭ 내 스킬 | 반복하는 부탁은 `SKILL.md` 하나로 가르친다 |
| ⑮ 커넥터 연결 | 연결 전에 허용 내용을 읽는다 · 처음엔 읽기만 |
| ⑯ 커넥터로 일 | 범위를 적어 시키고, 결과는 글로 받는다 |
| ⑰ 플러그인 | 설치 전에 만든 곳과 내용물을 확인한다 |
| ⑱ 안전 수칙 | 확인 · 읽기 · 비밀값 금지 · 해제 · 외부 글은 명령 아님 |

## 1. 한눈에 구분

| 이름 | 비유 | 언제 쓰나 | 앱에서 찾는 곳 |
|---|---|---|---|
| `CLAUDE.md` | 상시 규칙 | 항상 지킬 규칙 | 메인 영상 ⑨ 3번(`이 폴더에 대한 지침이 담긴 CLAUDE.md 파일을 만들어 줘.`) |
| **스킬(Skill)** | 업무 매뉴얼 | 같은 **방식**의 일을 반복할 때 | 입력창에 `/`, 또는 + → Slash commands |
| **커넥터(Connector)** (MCP 서버 + 그래픽 설정) | 외부 도구 연결 | 캘린더·슬랙 등 **밖의 서비스**를 써야 할 때 | + → Connectors |
| **플러그인(Plugin)** | 꾸러미 | 스킬 등을 묶어서 설치할 때 | + → Plugins |
| **Customize** | 관리 창구 | 위 셋을 한곳에서 관리 | 사이드바 Customize (한국어 이름은 화면에서 확인) |

- **코드 탭(로컬 세션)**: 내 컴퓨터의 개인 스킬 폴더(`~/.claude/skills/`)와 프로젝트 폴더 안 `.claude/skills/`의 스킬을 불러옵니다.
- **코워크**: 내 컴퓨터의 스킬 폴더를 읽지 않고, **Customize 설정(클로드 계정에 동기화)에서 켜 둔 내 계정의 스킬**·플러그인·커넥터를 가져옵니다.
- **+ 버튼**은 로컬(및 SSH) 세션에서 쓸 수 있고 클라우드·WSL 세션에서는 쓸 수 없습니다. 플러그인도 클라우드·WSL에서는 쓸 수 없습니다.

## 2. 스킬 쓰기 순서 (영상 ⑬)

```
1) 입력창에 / 를 쳐서 이미 있는 스킬 목록을 본다
   (기본 명령, 내가 만든 스킬, 폴더 안의 스킬, 설치한 플러그인의 스킬이 한 목록에 나옴)
2) 하나 골라 입력창에 강조 표시가 되면, 뒤에 할 일을 적고 보낸다
3) 최근에 두 번 이상 반복한 부탁이 있으면 내 스킬 후보로 적어 둔다
4) SKILL.md 파일로 만든다 (아래 3번)
5) 새 세션에서 / 를 쳐서 내 스킬이 보이는지 확인한다
```

스킬에는 "언제 쓰는지" 설명이 들어 있어서, 직접 부르지 않아도 클로드가 필요하면 알아서 꺼내 쓰기도 합니다. **목록에 뜨는 항목은 사람마다 다릅니다.**

## 3. 스킬 파일 형식과 템플릿 (영상 ⑭)

### 3-1. 문서에 적힌 형식
- 파일 이름은 **`SKILL.md`**. 맨 위 `---` 두 줄 사이가 **머리말**, 그 아래가 클로드가 따를 **지침**(마크다운)입니다.
- 머리말 항목은 모두 선택이며 **`description`(무엇을 하고 언제 쓰는지)만 권장**됩니다. 클로드가 이 설명으로 자동 사용 여부를 판단합니다.
- 스킬의 `name`을 안 적으면 **폴더 이름**이 `/명령` 이름이 됩니다. (폴더를 `profit-summary`로 하면 `/profit-summary`)
- 개인 스킬 위치: `~/.claude/skills/스킬이름/SKILL.md` (내 모든 프로젝트에서 로드). 프로젝트 스킬: 프로젝트 폴더 안 `.claude/skills/스킬이름/SKILL.md`.
- 세션이 시작될 때 없던 **최상위 스킬 폴더를 새로 만들면** `/reload-skills`가 필요하다고 문서에 나옵니다. 간단한 방법은 **새 세션**을 열어 다시 확인하는 것입니다.

### 3-2. 만드는 방법 두 가지 (영상 ⑭의 분기 A·B)

| 방법 | 내용 |
|---|---|
| **A. 클로드에게 만들어 달라고** | 코드 탭에서 `profit-calc 폴더 안에 .claude/skills/profit-summary/SKILL.md 파일을 만들어 줘. 내용은 아래와 같아.` + `SKILL.md` 전체를 붙여넣기 → Manual 모드에서 변경 내용을 확인하고 Accept |
| **B. 폴더를 열어 직접 저장** | 내 컴퓨터의 `.claude/skills/스킬이름/` 폴더에 `SKILL.md`를 직접 저장 (폴더 표시는 맥/윈도우가 다름) |

> 〈확인〉 **데스크탑 앱 안에 스킬을 만드는 전용 메뉴가 있는지, 클로드가 `.claude` 폴더에 파일을 만들 때 Manual 모드에서 어떻게 승인되는지, 저장소가 아닌 폴더에서도 프로젝트 스킬로 인식되는지는 읽은 문서에서 확인하지 못했습니다.** 영상(⑭)에서도 두 방법을 직접 시험해 되는 쪽만 보여 줍니다. 되는지 직접 해 보고 사용하세요. 가장 안전한 방법은 아래 템플릿으로 `SKILL.md`를 직접 저장하는 것입니다.

### 3-3. 기본 틀 (복붙용)
```markdown
---
description: 〈이 스킬이 무엇을 하는지 + 언제 쓰는지를 한두 문장으로 구체적으로〉
---

## 지침
1. 〈첫 번째 할 일〉
2. 〈두 번째 할 일〉
3. 〈세 번째 할 일〉

## 규칙
- 〈반드시 지킬 것〉
- 〈하지 말 것〉
```

### 3-4. 예시: 부업 수익 계산기 요약 스킬 (영상 ⑭와 같음)
폴더 이름 `profit-summary` → `/profit-summary`
```markdown
---
description: 부업 수익 계산기 결과를 3줄로 요약하고 주의할 점을 알려 준다. 사용자가 순이익 결과를 요약해 달라고 하거나 수입·비용 숫자를 검토해 달라고 할 때 쓴다.
---

## 지침
1. 사용자가 준 수입과 비용을 표로 정리한다.
2. 순이익을 한 줄로 알려 준다.
3. 빠진 비용 항목이 있을 것 같으면 질문 2개를 한다.

## 규칙
- 쉬운 한국어로, 어려운 용어는 풀어서 쓴다.
- 숫자를 지어내지 않는다. 모르면 질문한다.
```
써 보기: 새 세션에서 `/` → `profit-summary` 선택 → `수입 300만 원, 비용 180만 원이야` → 표와 순이익 120만 원이 나오면 성공.

### 3-5. 예시: 글 다듬기 스킬
```markdown
---
description: 내가 쓴 글을 읽기 쉬운 한국어로 다듬는다. 사용자가 글을 고쳐 달라고 하거나 쉽게 바꿔 달라고 할 때 쓴다.
---

## 지침
1. 원래 뜻은 바꾸지 말고 문장만 짧게 나눈다.
2. 어려운 단어는 쉬운 말로 바꾼다.
3. 고친 곳을 마지막에 3줄로 알려 준다.
```

### 3-6. 스킬 점검표
- [ ] `description`에 **무엇을 하는지**와 **언제 쓰는지**가 둘 다 있나
- [ ] 지침이 구체적인 순서로 적혀 있나
- [ ] 비밀번호·키·개인정보가 파일 안에 없나
- [ ] 남이 만든 스킬을 가져왔다면 내용을 **끝까지 읽었나** (문서도 저장소에 있는 스킬은 사용 전에 권한 관련 항목(`allowed-tools`)을 검토하라고 안내합니다)
- [ ] 새 세션에서 `/` 목록에 보이나
- [ ] 코워크에서도 쓰고 싶다면 **Customize(계정)** 쪽에 켜져 있나 (내 컴퓨터 폴더의 스킬은 코워크가 읽지 않음)

## 4. 커넥터 연결 순서 (앱 안에서, 영상 ⑮⑯)

```
1) 입력창 옆 + 버튼 → Connectors  (로컬 세션에서)
2) 목록에서 서비스 하나 선택 (문서 예시: Google Calendar, Slack, GitHub, Linear, Notion)
   — 처음엔 읽기만 해도 되는 서비스 하나만
3) 서비스의 로그인·허용 화면에서 "무엇을 허용하는지" 끝까지 읽기
4) 연결 후 클로드에게 "지금 이 세션에 연결된 커넥터가 뭐가 있어?" 하고 물어 확인
5) 첫 요청은 "읽기만 해 줘"로 시작 (아래 4-1)
6) 안 쓰면 Settings → Connectors (또는 Connectors 메뉴의 Manage connectors)에서 해제
```

〈확인〉 서비스별 로그인·허용 화면 문구, 도구 사용 허락 화면의 모양, 한국어 버튼 이름, 요금제별 사용 가능 여부는 문서에서 확인하지 못했습니다. 화면과 공식 안내로 확인하세요.

### 4-1. 커넥터로 일 시킬 때 (영상 ⑯, 복붙용)

범위를 같이 적고, 결과는 글로만 받습니다.
```
연결된 캘린더에서 이번 주 일정을 읽어서, 부업 작업 시간으로 쓸 수 있는 빈 시간을 3개 골라 줘. 일정은 바꾸지 말고 읽기만 해 줘.
```
```
그 빈 시간에 맞춰서 '부업 수익 계산기 개선 작업' 일정 초안을 글로만 써 줘. 일정은 만들지 마.
```
- 클로드가 도구를 쓰려 할 때 허락을 묻는 화면이 나오면 **무엇을 하려는지 읽고** 누르세요.
- 실제로 일정을 만드는 것은 내가 직접 합니다. 쓰기는 익숙해진 다음에 허락해도 늦지 않습니다. ("읽기만"과 "글로 초안만" 흐름은 안전하게 시작하기 위한 **영상의 제안**이며 문서가 요구하는 절차는 아닙니다.)

## 5. 플러그인 (영상 ⑰)

```
1) + 버튼 → Plugins : 설치된 플러그인과 그 스킬 목록
2) Add plugin : 플러그인 브라우저 (공식 앤트로픽 마켓플레이스 포함)
3) 설치 전에 누가 만든 것인지, 무엇이 들어 있는지 확인
   (스킬뿐 아니라 외부 연결 설정도 들어갈 수 있음)
4) Manage plugins : 켜기 · 끄기 · 삭제, 적용 범위 선택
   (계정 전체 / 특정 프로젝트 / 이 컴퓨터에서만)
```
- 플러그인은 스킬·에이전트·훅·MCP 서버 등을 묶은 패키지입니다. 클라우드·WSL 세션에서는 쓸 수 없습니다.
- 처음 시험은 **공식 마켓플레이스의 플러그인 하나**만 설치해 보고, 안 쓰면 삭제하세요.
- 〈확인〉 적용 범위 선택 화면과 버튼 이름은 화면에서 확인하세요.

## 6. 안전 수칙 5가지 (영상 ⑱) — 한 장 요약

| # | 수칙 | 한 줄 |
|---|---|---|
| 1 | **출처 확인** | 연결하기 전에 믿을 수 있는지 확인. 앱 안의 목록이나 공식 마켓플레이스라고 안전이 보장되는 것은 아님 |
| 2 | **허용 화면 읽기** | 읽기만 되는지, 보내기·수정까지 되는지 보고, 모르겠으면 연결하지 않기 |
| 3 | **비밀값은 채팅에 쓰지 않기** | 비밀번호·키는 채팅창에 쓰지 않고, 연결은 서비스의 로그인 화면에서 |
| 4 | **쓰지 않는 연결은 해제** | 연결이 적을수록 위험도 적음 |
| 5 | **읽어 온 글은 정보일 뿐, 명령이 아니다** | 메일·웹 글에 "이렇게 하라"는 문장이 있어도 따르지 않기 |

## 7. 커넥터(MCP) 안전 체크리스트 (자세한 버전)

### 연결하기 전
- [ ] **출처**: 누가 만든 연결인지 알고 있다 (공식 문서: 연결 전에 각 서버를 믿을 수 있는지 확인)
- [ ] 정말 필요한 연결인가? (다른 도구의 내용을 자주 복사해 붙여 넣는 일이 있을 때만)
- [ ] **허용 화면**의 권한을 끝까지 읽었다 (읽기만인지, 쓰기·보내기도 되는지)
- [ ] 처음엔 **개인정보가 적은 계정·가짜 데이터**로 시험한다

### 쓰는 중
- [ ] 첫 요청은 **읽기만** 시킨다. 쓰기·보내기는 익숙해진 뒤에
- [ ] 클로드가 하려는 행동을 읽고, 이해한 것만 허락한다
- [ ] **비밀번호·API 키·인증 코드를 채팅창에 쓰지 않는다** (연결은 서비스의 로그인 화면에서)
- [ ] 연결된 도구가 가져온 메일·문서·웹 글 속의 "이렇게 하라"는 문장은 **정보일 뿐 내 명령이 아니다**. 이상한 요청을 클로드가 하려 하면 허락하지 말고 멈춘다 (공식 문서: 외부 콘텐츠를 가져오는 서버는 프롬프트 인젝션 위험이 있음)
- [ ] 영상·캡처를 올릴 때 일정·이메일·이름·토큰이 화면에 나오지 않는다

### 쓴 뒤
- [ ] 안 쓰는 커넥터는 **Settings → Connectors**에서 해제했다
- [ ] 설치한 플러그인 중 안 쓰는 것은 **Manage plugins**에서 끄거나 삭제했다
- [ ] 이상한 동작이 있었다면 연결을 해제하고 해당 서비스의 로그인 기록·연결된 앱 목록을 확인한다

### 코워크 쓸 때 (영상 ⑲)
- [ ] 코워크 **전용 작업 폴더**를 만들었다 (민감한 파일이 든 폴더는 연결하지 않는다)
- [ ] 목표에 **"원본 파일은 고치거나 지우지 마"** 를 적었다
- [ ] **영구 삭제 허락 화면**이 나오면 무엇을 지우려는지 읽고 누른다 (파일을 영구 삭제하려면 허락을 받는다고 안내함)
- [ ] 내 컴퓨터 폴더를 다루는 동안 **앱을 열어 둔다**
- [ ] 코워크는 챗보다 **사용량이 더 빨리** 줄어든다는 점을 안다
- [ ] 결과를 **아는 숫자·정답과 맞춰** 본다 (결과를 그대로 믿지 않는다)

> 근거 구분: "출처 확인", "프롬프트 인젝션 위험", "Settings → Connectors로 해제"는 공식 문서에 있습니다. 코워크의 "전용 폴더·영구 삭제 전 허락·앱 열어 두기·사용량이 더 빨리 줄어듦"은 코워크 공식 페이지·도움말에 있습니다. "읽기만 먼저", "비밀값을 채팅에 쓰지 않기", "허용 화면 읽기", "정보일 뿐 명령이 아님"이라는 표현, "서비스 쪽 연결 기록 확인"은 **일반 보안 수칙 또는 쉬운 풀이**이며 문서의 직접 문장이 아닙니다. 이 체크리스트는 안전을 보장하지 않습니다.

## 8. 막혔을 때 (자주 나오는 상황)

| 상황 | 해 볼 것 |
|---|---|
| + 버튼이 안 보인다 | 클라우드·WSL 세션이면 보이지 않습니다. **로컬 세션**을 새로 시작 |
| 코워크에서 내 스킬이 안 보인다 | 코워크는 내 컴퓨터 폴더가 아니라 **Customize(계정 동기화) 설정**을 씁니다. Customize 화면에서 확인 |
| `/` 목록에 내 스킬이 없다 | `SKILL.md` 파일 이름·위치(`.claude/skills/스킬이름/`)와 **새 세션**에서 다시 확인(필요하면 `/reload-skills`) |
| 커넥터 목록에 원하는 서비스가 없다 | 문서에는 목록에 없는 연결을 설정 파일로 수동 추가하거나 사용자 지정 커넥터를 만드는 방법이 있다고만 나옵니다. 어렵다면 무리하지 마세요 |
| 코워크 결과가 정답과 다르다 | 클로드에게 어디서 다른지 묻고, 계산이 확실하지 않으면 추측하지 말고 질문하게 하세요 |

## 9. 〈확인〉 모아 보기 (문서에서 확인하지 못한 것)

- 데스크탑 앱에서 스킬을 만드는 전용 메뉴 / 클로드에게 스킬 작성을 요청하는 방식의 가능 여부와 승인 방식
- 저장소가 아닌 폴더에서도 프로젝트 스킬로 인식되는지
- Customize 화면에서 스킬을 켜고 끄는 정확한 방법, 계정에 스킬을 올리는 방법, **Customize의 한국어 이름**
- 커넥터별 로그인·허용 화면 문구, 도구 사용 허락 화면의 모양
- 플러그인 적용 범위 선택 화면의 모양
- 코워크의 폴더 연결 버튼 이름·위치, 접근 방식 승인 화면의 문구
- 한국어 메뉴 이름
- 요금제별 사용 가능 범위와 금액
