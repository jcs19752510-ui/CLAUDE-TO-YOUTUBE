# 쇼츠 대본 10편 — "클로드 코드로 24일" 시리즈

- 형식: 세로 9:16, **40~50초**, 대사 약 200~240자(말 속도 1분 약 280자 기준)
- 표기: **[훅]** 첫 3초 · **[말]** 대사 · **[화면]** 보여줄 것 · **[자막]** 큰 글씨 · **[마무리]** 마지막 3초
- 빈칸 `〈 〉`는 직접 채울 것. 근거(커밋·결정 번호)는 촬영 전 사실 확인용이며 영상에는 넣지 않아도 됩니다.
- 공통 규칙: 첫 문장은 **결과·충격·질문**으로 시작 / 마지막 문장은 **다음 행동 1개**(구독, 댓글, 풀영상) / 종목 화면은 예시 처리 + "투자 권유 아님"

## 쇼츠 1. 대체공휴일 때문에 AI 코드가 멈췄다 ⭐

- 제목: `AI가 만든 코드가 멈춘 이유, 대체공휴일이었습니다`
- **[훅 0~3초]** (화면: 어제 날짜에서 멈춘 화면, 빨간 테두리)
  "AI가 만든 서비스가, 대체공휴일 때문에 멈췄습니다."
- **[말]**
  "이 서비스는 공공 데이터를 다음 영업일에 받아옵니다. 그런데 10월 5일이 대체공휴일이었어요. 데이터가 안 나오는 동안 프로그램은 실패를 세 번 쌓았고, 이렇게 판단했습니다. '이 날은 안 되는 날이다.' 그래서 데이터가 공개된 뒤에도 그 날을 영원히 건너뛰었습니다."
- **[화면]** 달력 그래픽(10/2 금 → 주말 → 10/5 월 대체공휴일 → 10/6 화), 실패 횟수 `1 2 3`이 올라가다 `영구 포기` 도장.
- **[자막]** `아직 안 나온 것 ≠ 실패한 것`
- **[마무리]**
  "고쳐 줘 말고, 재현 시험부터 쓰게 하세요. 풀영상은 프로필 링크에서 보세요."
- 근거: DEC-092, 커밋 `4bf188b`(10/6), 재현 시험 `tests/integration/test_catchup_attempt_cap_db.py`

## 쇼츠 2. 클로드한테 "직접 해봐"라고 시키는 규칙 한 줄

- 제목: `클로드가 자꾸 나한테 시킨다면? 이 한 줄만 쓰세요`
- **[훅]** "클로드가 '직접 해 보세요'라고 하면, 이렇게 하세요."
- **[말]**
  "클로드 코드가 '내 PC에서 실행해 보세요' 하고 일을 떠넘긴 적 있으시죠? 규칙 파일에 이 한 줄을 넣으세요. '시험은 네가 직접 한다. 나한테 시키지 않는다.' 그랬더니 클로드가 윈도우용 실행기를 직접 내려받아서, 스크립트 22건을 스스로 돌려 확인했습니다."
- **[화면]** `CLAUDE.MD`에 한 줄이 타이핑 → 터미널에서 22건 통과 로그(`22/22`).
- **[자막]** `내부 테스트는 에이전트가 직접 한다`
- **[마무리]** "규칙 파일 템플릿은 설명란에 무료로 올려 뒀어요. 저장해 두세요."
- 근거: CLAUDE.MD 상시 규칙 1, DEC-094(PowerShell 7.4.5, 22/22)

## 쇼츠 3. 하루에 커밋 74개? AI 개발의 하루

- 제목: `AI랑 개발하면 하루에 74번 저장됩니다 (실제 기록)`
- **[훅]** "하루에 74번 저장한 날이 있습니다."
- **[말]**
  "저장 기록을 커밋이라고 하는데, 24일 동안 199개를 쌓았습니다. 처음 두 주는 하루에 한두 개였는데, 10월 6일 하루에만 74개가 쌓였어요. AI가 갑자기 똑똑해진 걸까요? 제가 일하는 방식을 바꿔서 그렇다고 생각합니다. 규칙을 정하고, 역할을 나누고, 시험을 자동으로 돌렸거든요."
- **[화면]** 날짜별 막대 그래프(9/14~10/7), 10/6 막대가 튀어 오른다.
- **[자막]** `24일 · 199커밋 · 하루 최대 74`
- **[마무리]** "방법은 풀영상에 다 담았습니다."
- 근거: 일자별 커밋 집계(10/2 41개, 10/6 74개). "일하는 방식 때문"은 본인 해석이므로 본인 판단으로 수정.

## 쇼츠 4. AI 에이전트 13명 조직도

- 제목: `AI 직원 13명으로 개발팀을 꾸렸습니다`

- **[말]**
  "클로드에게 역할을 나눠 주는 걸 서브에이전트라고 합니다. 시장 조사, 기획, 설계, 디자인, 개발, 시험, 보안, 배포 연습, 문서, 배포, 확인까지 열세 명이에요. 그런데 딱 한 가지, 실제 배포만은 제 승인 없이는 못 합니다."

## 쇼츠 5. 비밀번호 12자를 8자로 바꾼 이유

- 제목: `AI가 만든 보안 규칙을 제가 바꾼 이유`
- **[훅]** "AI가 정한 비밀번호 규칙을, 제가 직접 줄였습니다."
- **[말]**
  "처음 AI는 비밀번호를 최소 12자리로 만들었습니다. 안전하긴 하죠. 그런데 개인용 서비스에서 쓰기엔 번거로워서, 제가 8자리로 줄이라고 시켰습니다. 안전과 편의 사이의 균형은 AI가 아니라 제가 정해야 하는 일이니까요."
- **[화면]** 입력창 `12자 이상` → `8자 이상`으로 바뀌는 연출, 좌우 저울(안전 ⚖ 편의).
- **[자막]** `안전 vs 편의 = 내가 정한다`
- **[마무리]** "여러분이라면 몇 자로 하시겠어요? 댓글로 알려 주세요."
- 근거: 커밋 `898bc71`(10/5, 사용자 요청), DEC-072
- ⚠ 주의: "비밀번호는 짧아도 된다"로 오해되지 않게, 공개 서비스라면 더 엄격하게 하라는 한 줄을 설명란에 넣으세요.

## 쇼츠 6. AI가 만든 에러 메시지가 틀렸을 때

- 제목: `로그인 실패? 비밀번호 문제가 아니었습니다`
- **[훅]** "비밀번호가 틀렸다는데, 비밀번호는 맞았습니다."
- **[말]**
  "로그인이 안 돼서 화면에 '비밀번호 오류'가 떴어요. 그런데 진짜 원인은 서버끼리 주고받는 내부 열쇠가 서로 안 맞은 거였습니다. AI가 만든 화면이 원인을 잘못 분류해서 비밀번호 탓을 한 거예요. 그래서 에러를 정확히 구분해서 보여 주도록 고쳤습니다."
- **[화면]** 로그인 화면에 `비밀번호가 올바르지 않습니다` → 로그에서 `401 내부 토큰 불일치`가 드러남.
- **[자막]** `에러 문구 ≠ 진짜 원인`
- **[마무리]** "클로드에게 '에러 문구를 확인한 뒤에만 원인을 말해'라고 시키세요."
- 근거: 커밋 `7189c8a`(10/5), `996f7b4`

## 쇼츠 7. 배포를 세 번 바꾼 이유

- 제목: `서버를 세 번 바꿨습니다. 결국 제 노트북으로 돌아왔어요`
- **[훅]** "서비스를 세 번 옮겼는데, 결국 제 노트북으로 돌아왔습니다."
- **[말]**
  "처음엔 클라우드 서버에 올릴 준비를 했고, 다음엔 무료 서버와 무료 데이터베이스로 옮겼습니다. 곧 유료 요금제로 바꿨죠. 그런데 개인용이라는 목적을 다시 생각해서, 결국 지금은 내 노트북에서만 돌립니다. 비용, 관리, 위험을 따져 보니 그게 맞았어요."
- **[화면]** 화살표 4개: `클라우드 서버` → `무료 서버` → `유료 요금제` → `내 노트북`
- **[자막]** `목적이 방식을 정한다`
- **[마무리]** "AI가 아니라 내가 목적을 정해야 합니다."
- 근거: 10/3 Oracle 배포 키트(DEC-060)→ Render+Neon 무료(DEC-063) → 10/6 유료 전환 → 10/6 "로컬 노트북에서만 테스트" 규칙. 순서·표현은 촬영 전 본인 기억과 대조.

## 쇼츠 8. 챗 / 코워크 / 클로드 코드, 3초 선택법

- 제목: `클로드 뭘 써야 하죠? 3초 선택법`
- **[훅]** "챗, 코워크, 코드. 뭘 써야 할지 3초 만에 정하는 법."
- **[말]**
  "질문은 딱 하나입니다. 결과물이 뭐가 되길 원하세요? 그냥 답변과 생각 정리면 챗. 정리된 파일이나 문서면 코워크. 계속 돌아가는 서비스나 앱이면 클로드 코드입니다. 저는 주식 분석 서비스를 만들었으니 처음부터 끝까지 클로드 코드를 썼어요."
- **[화면]** 3칸 표 `답변=챗 / 파일=코워크 / 서비스=코드`, 칸마다 아이콘.
- **[자막]** `결과물이 뭐냐?`
- **[마무리]** "저장해 두고 헷갈릴 때 보세요."
- 근거: 이 프로젝트는 클로드 코드 중심(저장소 이력). 챗·코워크를 실제로 썼는지는 저장소로 확인 불가 → 사용했다는 표현은 쓰지 않음.

## 쇼츠 9. 개발자가 AI에게 절대 안 맡기는 3가지

- 제목: `AI에게 절대 안 맡기는 3가지`

## 쇼츠 10. 시험 결과서를 왜 쓰게 했나

- 제목: `AI에게 "확인 못 한 것도 적어"라고 시키세요`
- **[훅]** "AI의 '잘 됐습니다'를 믿지 마세요."
- **[말]**
  "저는 클로드가 일할 때마다 시험 결과서를 쓰게 했습니다. 여기에 꼭 넣게 한 항목이 하나 있어요. '확인하지 못한 것과 위험.' 잘 된 것만 보고하면 안 되니까요. 결과서가 마흔 개 넘게 쌓였고, 나중에 문제가 생겼을 때 어디서부터 의심해야 하는지 알려 줬습니다."
- **[화면]** 결과서 문서 한 장, `확인하지 못한 것` 항목에 형광펜.
- **[자막]** `확인 못 한 것을 적게 하라`
- **[마무리]** "풀영상에서 규칙 파일 전체를 공개했습니다."
- 근거: CLAUDE.MD 상시 규칙 3, `docs/qa/` 결과서(40여 개)
