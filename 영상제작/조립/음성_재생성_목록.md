## 5. 만드는 순서 (요청 수·한도 절약)

**선행 조건 — 스크립트가 아직 ⑪~⑳을 읽지 못합니다 (이번 작업에서는 스크립트를 고치지 않았음).**

| 파일 | 고칠 곳 |
|---|---|
| `조립/common.py` | `CHAPTERS`에 `⑪`~`⑳` 추가(20개), `CHAPTER_TITLES`도 갱신(현재 값은 15분본 이전 구성), `parse_paragraphs`의 정규식 `[①-⑩]` → `[①-⑳]`. `voice_name`은 그대로(`V11_p00`처럼 2자리 번호 동작) |
| `조립/make_voice.py` | `--only`의 도움말 "1~10" → "1~20". 코드는 `CHAPTERS`만 늘리면 동작 |
| `조립/assemble.py`, `조립/build_draft.py` | 챕터 목록·`SPEC`·그래픽 매핑이 15분본/구형 기준. 재생 순서(⑪이 ⑦ 안, ⑩이 맨 끝)에 맞게 별도 순서표가 필요 |
| 그래픽(`그래픽/…`) | 챕터 카드 `11_챕터07…`, 5줄 요약·엔드카드 등은 15분본 기준. 새 챕터 ⑫~⑳ 카드·진행 바(10/30, 20/30)는 아직 없음 |

> 위 수정 전에 `make_voice.py`를 그대로 돌리면: 옛 파서는 ⑪~⑳ 구간을 **무시**하므로 ①~⑩에는 영향이 없지만, ⑪~⑳ 음성은 만들어지지 않습니다. (이 대본은 ⑪~⑳을 첫 `---` 아래에 모아서 옛 파서가 ①~⑩을 잘못 읽지 않게 했습니다. 실제로 옛 파서로 읽어 ①~⑩ 문단 수가 15분본과 같은 것을 확인했습니다.)

**1단계 — 수정 문단 3개 (문단 모드, 요청 3회).** 챕터 모드로 돌리면 챕터 전체를 다시 만들어 재사용 음성이 사라지므로 **문단 모드**를 씁니다.
```
(사용자가 직접) 음성/V01_p01.mp3, 음성/V02_p02.mp3, 음성/V10_p01.mp3 를 지운다
python 조립/make_voice.py --mode paragraph --only 1
python 조립/make_voice.py --mode paragraph --only 2
python 조립/make_voice.py --mode paragraph --only 10
```
- ⚠ **`--mode paragraph` 없이** 실행하면(기본은 챕터 모드) 보관된 옛 원본 `_원본/chapter_NN.mp3`를 다시 분리해 **옛 문장의 음성이 되살아납니다.** ①②⑩에는 반드시 `--mode paragraph`를 붙이세요.
- 문단 모드는 **이미 있는 파일은 건너뛰고** 없는 파일만 만듭니다(`--overwrite` 쓰지 마세요: 챕터 전체를 다시 만듭니다).
- **`--resplit`을 ①·②·⑩에 쓰지 마세요.** `음성/_원본/chapter_01.mp3`, `chapter_02.mp3`, `chapter_10.mp3`는 15분본 글로 만든 원본이라, 다시 분리하면 옛 음성으로 덮어씁니다.
- 참고: 문단 모드 음성은 챕터 모드와 억양 연결이 조금 다를 수 있으니, 듣고 어색하면 그 문단만 다시 만드세요.

**2단계 — 새 챕터 11개 (챕터 모드, 요청 11회).** ⑨, ⑪~⑳을 챕터마다 1회씩.
```
python 조립/make_voice.py --only 9
python 조립/make_voice.py --only 11
… (12~20 반복)
```
- 챕터 모드는 챕터마다 요청 1회 → 문단 쉼으로 자동 분리하므로 요청이 적습니다. 분리 후 `⚠ 길이 이상` 표시가 나온 파일은 직접 들어 보세요.
- 하루 무료 한도에 걸리면 "이미 만든 파일은 건너뛰고 이어서" 같은 명령을 다시 실행합니다(약 15시간 뒤). 한도·요금은 Google 공식 안내에서 확인하세요(11번 가이드의 "확인 필요").

**요청 수 비교**: 권장(1단계 3회 + 2단계 11회) = **14회**. 전부 챕터 모드로 새로 만들면 20회(재사용 42개 폐기), 전부 문단 모드로 새로 만들면 96회.
