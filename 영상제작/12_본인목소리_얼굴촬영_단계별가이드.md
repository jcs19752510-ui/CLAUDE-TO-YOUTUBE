## 1단계. 장비와 프로그램 준비

**필요한 것**: 마이크, 카메라, 조명, 프로그램 3개, 폴더.

**예시: 처음 시작하는 최소 세트**

| 항목 | 예시 | 이유 |
|---|---|---|
| 마이크 | 스마트폰 유선 이어폰의 마이크(입에서 주먹 하나 거리) | 소리가 나쁘면 시청자가 바로 나갑니다. 마이크가 가장 우선입니다. |
| 카메라 | 내 스마트폰, 가로 촬영 | 별도 카메라는 필요 없습니다. |
| 거치대 | 책 몇 권 위에 폰을 세우기 | 손으로 들면 흔들립니다. |
| 조명 | 창문을 마주 보고 앉고, 낮에 촬영 | 뒤에서 빛이 오면 얼굴이 어두워집니다. |
| 프로그램 | OBS Studio(화면 녹화), Vrew(말 자르기·자막), CapCut(이어 붙이기) | 모두 무료로 시작할 수 있습니다. ⚠ 요금제와 기능은 확인하세요. |

**폴더 만들기 예시** (바탕화면)
```
클로드코드영상/
 ├ 01_화면녹화/   ← B1~B11 저장
 ├ 02_얼굴촬영/   ← A1~A10 저장
 ├ 03_그래픽/     ← 제가 만든 mp4 10개 복사
 ├ 04_자막/       ← 강조자막_초안.srt
 ├ 05_음악/
 └ 07_완성본/
```

**체크**: 이어폰을 꽂고 10초 녹음해 들어 보세요. 웅웅거리는 소리가 심하면 방을 옮기세요.

## 2단계. 사실 확인과 연습

**필요한 것**: 대본의 `〈확인〉` 목록, 스톱워치, 공식 문서 화면.

**예시 ① 사실 확인 (대본 고치기)**

| 대본의 문장 | 확인 방법 | 결과에 따라 고치기 |
|---|---|---|
| "공식 문서의 설치 명령을 그대로 붙여넣고…" | 공식 설치 문서를 열어 지금 명령을 확인 | 설치 방법이 바뀌었으면 ④ 챕터 문장을 바꾸세요. |
| "시프트 탭을 누르면 모드가 바뀝니다" | 내 컴퓨터에서 Shift+Tab을 직접 눌러 봄 | 안 되면 실제 단축키로 고치세요. |
| "Esc를 두 번 누르면 되돌리는 메뉴가 나와요" | 클로드 코드에서 직접 눌러 봄 | 동작이 다르면 문장을 고치세요. |

**예시 ② 계산기 연습 (시간 재기)**

1. 스톱워치를 켭니다. 빈 폴더 `profit-calc`를 만들고 `claude`를 실행합니다.
2. 요청: `부업 수익 계산기 웹페이지 만들어 줘…`
3. 결과 화면이 뜨면 스톱워치를 멈춥니다. 예를 들어 **7분 20초**가 나왔다고 합시다.

| 대본 원문 | 수정 |
|---|---|
| "걸린 시간은 5분입니다." | "걸린 시간은 약 7분입니다." |
| "처음엔 에러투성이였어요." | 실제로 에러가 **났을 때만** 유지하고, 안 났으면 삭제하세요. |

**예시 ③ 입에 맞게 고치기** (`07_읽기용_대본.md`를 소리 내어 읽으며)

| 원문 | 말하기 편하게 |
|---|---|
| "컴퓨터에게 글자로 부탁하는 창일 뿐이에요." | "컴퓨터한테 글자로 부탁하는 창이에요." |

**예시 ④ 길이 계산**: 대사만 읽으면 약 9~10분입니다. 시연 3분 + 그래픽 2분 + 여백 1분을 더하면 15분 안팎이 됩니다.

## 3단계. 화면 녹화 (OBS)

**필요한 것**: OBS 설정, 녹화 전 정리, 클립별 녹화.

**예시: OBS 설정 (한 번만)** ⚠ 메뉴는 버전마다 다름
- 소스 `+` → **화면 캡처** 추가
- 설정 → 영상: 해상도 **1920×1080**, FPS **30**
- 설정 → 출력: 녹화 형식 `mkv`(꺼져도 파일 보존) → 끝난 뒤 `mp4`로 변환

**예시: 녹화 전 정리**

| 항목 | 예시 |
|---|---|
| 글자 크기 | 터미널 글꼴 14 → **22**(평소의 1.5배). 모바일에서 읽혀야 합니다. |
| 가릴 것 | 바탕화면 개인 파일, 알림, 메신저, `.env`, API 키, 로그인 이메일 |
| 데이터 | 수입 3,200,000 / 비용 1,150,000 같은 **가짜 숫자** |

**예시: 클립 B6 녹화 순서** (첫 프로젝트)

| 시각 | 할 일 |
|---|---|
| 00:00 | 녹화 시작, **3초 가만히** |
| 00:03 | 폴더 `profit-calc` 만들고 `claude` 실행 |
| 00:20 | 요청 입력 |
| 01:10 | 허락 화면에서 "예" 누르기 |
| 05:30 | 완성 → 브라우저에서 열고 숫자 입력 |
| 06:00 | **3초 가만히** 후 녹화 종료 |

- 파일 이름: `B6_첫프로젝트_1.mp4`
- 중간에 틀리면 **그 클립만** 다시 하세요.

## 4단계. 얼굴·목소리 촬영

**필요한 것**: 자리 세팅, 소리 점검, 읽기용 대본, 박수 신호.

**예시: A2 클립(통증 + 약속) 촬영**

1. 모니터에 `07_읽기용_대본.md`의 ② 챕터를 띄우고, 카메라 렌즈 바로 아래에 둡니다.
2. 녹화 시작 → **박수 한 번** → 1초 쉬고 읽기 시작
3. 문단 1을 읽고 **1초 쉬기** → 문단 2 읽기
4. **틀렸을 때**
   - 예: 세 번째 문장에서 틀림 → 그 **문단 처음부터** 다시 읽기
   - 편집에서 앞의 틀린 부분만 잘라 냅니다.
5. 끝나면 **3초 가만히**

**예시: 소리 점검 (30초)**
- 10초 말해서 녹음 → 이어폰으로 들어 보기
- 울림(웅웅)이 심하면 → 이불·커튼이 있는 곳, 작은 방으로 이동

**예시: 한 번에 몰아서 찍기**
- A1부터 A10까지 **같은 옷, 같은 자리, 같은 조명**으로 이어서 찍으세요.
- 날을 나눠 찍으면 얼굴 밝기와 옷이 달라 보입니다.

## 5단계. 편집

**필요한 것**: Vrew(말 자르기), CapCut(이어 붙이기), 샷 리스트.

**예시 ① Vrew로 말 자르기**

| 자동 인식된 글자 | 처리 |
|---|---|
| "음… 그래서 오늘은 이 세 가지를 합니다" | "음…"을 지우면 영상에서도 잘립니다. |
| 틀린 문단 앞부분 | 글자 선택 후 삭제 |
| 틀린 글자(잘못 인식) | 직접 고치기 (자동 자막은 항상 읽고 고쳐야 합니다) |

**예시 ② CapCut 타임라인 (영상 처음 25초)**

| 트랙 | 0:00~0:08 | 0:08~0:15 | 0:15~0:22 | 0:22~0:25 |
|---|---|---|---|---|
| 화면 | `B1 계산기 시연` | `B2 에러 화면` | `A1 얼굴` | `01_타이틀카드.mp4` |
| 목소리 | A1 목소리 | A1 목소리 | A1 목소리 | – |
| 자막 | – | "처음엔 이렇게 망했습니다" | – | – |

- 타임라인은 `06_샷리스트_편집타임라인.md`에 챕터별로 있습니다.

**예시 ③ 긴 대기를 줄이기**
- 설치가 90초 걸린다 → 클립을 4배속으로 → 약 22초가 됩니다.

**예시 ④ 강조 자막 위치 고치기**
- SRT 초안: 3:30에 "계속 쓸 도구가 필요하다 = 클로드 코드"
- 실제 영상에서 그 말이 나오는 시점이 3:12라면 → 자막을 3:12로 끌어서 옮기세요.
- 도식 영상이 이미 같은 문구를 보여 주면 자막은 지우세요.

**예시 ⑤ 자막 모양**
- 흰 글씨 + 검은 외곽선, 화면 **아래 1/3**, 한 줄 **15자 내외**
- 모바일에서 직접 열어 읽히는지 확인하세요.

**예시 ⑥ 배경음**
- 말소리보다 훨씬 작게(배경음 볼륨을 낮춤)
- 가요·팝은 쓰지 마세요. **무료·상업 이용 가능한 음원**만 쓰세요. 배경음 없이도 됩니다.

## 6단계. 내보내기

**필요한 것**: 내보내기 설정, 파일 이름, 스마트폰 확인.

**예시: 설정**

| 항목 | 값 |
|---|---|
| 해상도 | 1080p |
| 프레임레이트 | 30fps |
| 형식 | MP4 (H.264) |
| 파일 이름 | `클로드코드사용법_v1.mp4` |

**마지막 확인 예시**
1. 파일을 스마트폰으로 옮겨서 **처음부터 끝까지** 봅니다.
2. 자막이 작지 않은지, 소리가 갑자기 커지는 곳은 없는지, 화면에 키·계정이 나오지 않는지 확인합니다.
3. 최종 길이를 적어 둡니다. 예: **13분 40초**

## 7단계. 유튜브 업로드

**필요한 것**: 영상 파일, 썸네일, 제목, 설명란, 치트시트 링크.

**예시: 업로드 화면에 넣을 내용**

| 항목 | 예시 |
|---|---|
| 제목 | `2026 클로드 코드 사용법｜챗·코워크·코드 15분 총정리 (왕초보 · 무료 치트시트)` ⚠ 실제 길이가 13분이면 "14분"이나 "13분"으로 고치세요. |
| 썸네일 | 확정 이미지. ⚠ 업로드용은 JPG/PNG, 1280×720, 2MB 이하 권장 |
| 설명란 | 대본 부록 A를 복사한 뒤 **타임라인을 실제 영상 기준으로 수정** |
| 재생목록 | "클로드 코드 입문" 시리즈 재생목록(다음 편과 묶기) |
| 시청자층 | "아니요, 아동용이 아닙니다" |
| 최종 화면 | 마지막 20초에 구독 버튼 + 다음 영상 1개(엔드카드의 점선 박스 자리) |

**예시: 타임라인 다시 쓰기**
- 계획: `13:30 요약 + 오늘 할 일`
- 실제 편집본에서 그 장면이 12:10에 시작한다면 → `12:10 요약 + 오늘 할 일`로 바꾸세요.
- 시간이 틀리면 챕터 기능이 어긋납니다.

**예시: 공개 순서**
1. 먼저 **비공개**로 올립니다.
2. 처리가 끝나면 한 번 더 시청해서 이상이 없는지 봅니다.
3. 문제없으면 **예약** 공개로 바꿉니다. (예: 구독자가 많이 접속하는 시간대 직전. 데이터가 없으면 저녁 시간대로 시작해 보고 조정)

**예시: 공개 직후**
- 고정 댓글 올리기(`부록 B` 복사) → **고정**
- 설명란 치트시트 링크를 직접 눌러 열리는지 확인

## 8단계. 24시간·72시간 뒤 점검

**필요한 것**: YouTube Studio → 분석.

**예시: 24시간 뒤**

| 지표 | 보는 곳 | 해석 예시 |
|---|---|---|
| 노출 클릭률(CTR) | 개요 | 내 **이전 영상과 비교**하세요. 일반적인 기준은 채널·주제마다 다릅니다. 이전 영상보다 많이 낮으면 썸네일·제목을 교체하세요. |
| 평균 시청 지속 시간 | 개요 | 영상 길이의 어느 정도를 보는지 봅니다. |

> 이 영상은 썸네일에 **구글 아이콘**이 있어서 내용과 맞지 않습니다. CTR은 높은데 지속률이 낮다면 썸네일이 기대를 잘못 만든 것일 수 있습니다. 그때 교체하세요.

**예시: 72시간 뒤, 시청 지속률 그래프**

| 그래프에서 보이는 것 | 의심할 것 | 조치 |
|---|---|---|
| 0:00~0:30에 급락 | 첫 장면이 약함 | 첫 5초에 결과물을 더 빨리, 말을 빠르게 |
| 3:45(설치 챕터)에서 급락 | 설치 설명이 지루함 | 설치를 더 줄이거나 다음 영상에서 따로 다루기 |
| 8:00 부근 급락 | 개념 설명이 길음 | 예시를 앞에 두기 |
| 그래프가 완만 | 문제 없음 | 그대로 유지 |

**예시: 1주 뒤, 댓글에서 소재 찾기**
- 댓글: "설치할 때 'permission denied'가 나와요."
- → 다음 영상 소재로 쓰고, 댓글에 답을 달아 주세요.
